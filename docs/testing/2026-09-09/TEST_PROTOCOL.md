# Протокол повторного комплексного тестирования

## 1. Объект и среда

- Объект: поисковая система научной информации с авторизацией, индексацией, гибридным RAG и локальной LLM.
- Версия продукта: commit `80ffe1c`.
- Production: `https://search.5-42-117-227.sslip.io/`.
- Сервер: 8 vCPU, 12 ГБ RAM, PostgreSQL 18, Redis 7, Caddy, три Java-модуля.
- LLM: Qwen3-4B Q4_K_M, llama.cpp, 8 CPU-потоков, потоковая выдача; embeddings Nomic v1.5 отдельным процессом.
- Дата: 9 сентября 2026 года.

## 2. Критерии приёмки

| Проверка | Критерий |
|---|---|
| Модульные тесты | failures = 0; errors = 0 |
| Критический LLM-пакет | покрытие строк ≥ 60% |
| Основные LLM-клиенты | индивидуальные пороги CI от 70% до 90% |
| Production integration/security | все проверки пройдены, валидный TLS |
| Публичная HTTP-нагрузка | ошибки < 1%, p95 < 2 с при 20 клиентах |
| Поисковый SQL | ошибочные транзакции = 0 при 10 клиентах |
| RAG CPU-пилота, холодный кэш | 5/5 через LLM; цитаты ≥ 80%; retrieval p95 ≤ 2,5 с; TTFT p95 ≤ 16 с; total p95 ≤ 30 с |
| RAG CPU-пилота, рабочий кэш | 5/5 через LLM; TTFT p95 ≤ 5 с; total p95 ≤ 20 с |

Порог TTFT 16 секунд относится только к бесплатному CPU-профилю. Целевой SLO менее 5 секунд для нескольких одновременных пользователей требует GPU или внешнего API и не маскируется изменением теста.

## 3. Методика

### Модульное и интеграционное тестирование кода

В каждом Maven-модуле выполнена фаза `test` с JaCoCo. Проверены контроллеры, Spring Security, JWT, captcha, восстановление пароля, e-mail, поиск, сниппеты, параллельная индексация, RAG, векторный клиент, тематический анализ, кэш, circuit breaker, метрики и проверка цитат.

Результат: Search/LLM 65/65, Authorization 48/48, Email 6/6, всего 119/119.

### Production integration и security

`production-check.mjs` выполнил публичные GET-проверки, проверил captcha через auth-сервис, недоступность Swagger, OpenAPI, поиска и LLM-метрик для анонимного пользователя, security headers и TLS-сертификат. Результат: 9/9.

### Авторизованный RAG

`rag-load-test.mjs` создаёт временного посетителя, принимает приглашение в существующую группу, получает унаследованные источники, задаёт пять разных научных вопросов через SSE и проверяет `usedLlm`, режим retrieval и номера ссылок. Пароль не попадает в отчёт. После прогона пользователь удаляется сценариями только по префиксу `rag-evidence-...@example.test`.

### HTTP-нагрузка

Публичная главная страница проверена последовательно с 1, 5, 10 и 20 параллельными клиентами по 10 секунд. Максимальный этап: 1 690 успешных запросов, 167,25 RPS, p95 141,91 мс, ошибок 0.

### PostgreSQL

`pgbench` выполнял подготовленный read-only запрос по фактическому обратному индексу. Этапы: 1, 5 и 10 клиентов по 10 секунд. При 10 клиентах: 1 020 транзакций, 101,43 TPS, средняя задержка 98,59 мс, ошибок 0.

## 4. Результат и границы заключения

Все критерии зафиксированного пилотного профиля выполнены. При холодном кэше p95 составил 15,63/28,66 секунды, при рабочем кэше — 1,64/16,46 секунды. Статус: **полностью готово к эксплуатации в пилотном профиле**.

Заключение не распространяется на неограниченное число одновременных LLM-запросов. Приложение уже отделяет retrieval от генерации, возвращает источники до текста модели и корректно ограничивает очередь. Для горизонтального роста достаточно заменить `LLM_BASE_URL` на GPU/OpenAI-совместимый endpoint без изменения RAG и пользовательских данных.

## 5. Воспроизведение

```powershell
cd Searchengine_1
mvn test
cd ../authorization
mvn test
cd ../emailsender
mvn test
```

```powershell
node scripts/testing/production-check.mjs --base https://search.5-42-117-227.sslip.io/ --credentials-file deploy/.no-such --output docs/testing/latest/integration.json
node scripts/testing/load-test.mjs --base https://search.5-42-117-227.sslip.io/ --endpoint / --credentials-file deploy/.no-such --concurrency 20 --duration 10 --output docs/testing/latest/load-c20.json
```

Авторизованный RAG-тест требует временный код приглашения, подготовленный на сервере `prepare-rag-evidence.sh`; после теста обязателен `cleanup-rag-evidence.sh`. Значения приглашения и пароля не публикуются.

Необработанные JUnit/JaCoCo, JSON и pgbench-вывод сохранены рядом с протоколом.
