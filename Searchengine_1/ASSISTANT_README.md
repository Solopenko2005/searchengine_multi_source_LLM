# LLM-ассистент и анализ тематик

## Как это работает

1. Запрос пользователя лемматизируется и ищется существующим поисковым индексом.
2. Результаты фильтруются по выбранному пользователем набору документов и правам владельца.
3. Из каждого результата берётся релевантное окно текста, а не произвольное начало документа.
4. Контекст, профиль пользователя и ограниченная история диалога отправляются в OpenAI Responses API.
5. Модель получает явное правило считать содержимое документов недоверенными данными и не выполнять инструкции из них.
6. Ответ возвращается вместе со списком использованных источников. При недоступности API применяется локальный fallback.

Это RAG-настройка под документы пользователя, а не fine-tuning модели: исходные документы не меняют веса модели и добавляются только в контекст конкретного запроса.

## Настройка

Обязателен только ключ OpenAI API:

```text
OPENAI_API_KEY=your-api-key
```

Дополнительные параметры:

```text
OPENAI_ENABLED=true
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_MODEL=gpt-5.6-terra
OPENAI_REASONING_EFFORT=low
OPENAI_MAX_OUTPUT_TOKENS=1600
ASSISTANT_RATE_LIMIT_PER_MINUTE=30
OPENAI_TOPIC_MIN_CONFIDENCE=0.65
```

Код использует `POST /v1/responses`, повторы с учётом `Retry-After` при временных ошибках и Structured Outputs (JSON Schema) для анализа тематик. API-ключ не логируется и не возвращается клиенту.

ChatGPT Plus/Pro не предоставляет API-кредиты: OpenAI API требует отдельного ключа и billing в API-проекте.

## API

`POST /api/assistant/chat`:

```json
{
  "message": "Какие методы описаны в документах?",
  "history": [{"role": "user", "content": "Предыдущий вопрос"}],
  "site": "",
  "profileInstructions": "Отвечай как научный редактор, кратко и по-русски",
  "documentIds": [12, 18]
}
```

Ответ содержит `answer`, `sources`, `usedLlm` и признаки успешности. `documentIds` ограничивает RAG выбранными документами текущего пользователя.

- `GET /api/assistant/topics` — LLM-анализ и нормализация тематик; при отсутствии API — локальная агрегация;
- `GET /api/assistant/status` — доступность провайдера и выбранная модель.
- `GET /api/assistant/profile` — сохранённые инструкции и область документов пользователя;
- `PUT /api/assistant/profile` — сохранить профиль RAG в PostgreSQL.

Темы возвращаются со значением `confidence`; элементы ниже `OPENAI_TOPIC_MIN_CONFIDENCE`
отбрасываются. Поиск контекста требует присутствия всех значимых лемм запроса, что снижает
число нерелевантных фрагментов перед вызовом модели.

## Выбор модели

`gpt-5.6-terra` выбран как практичный баланс качества, задержки и стоимости. Для наиболее сложного анализа можно задать `OPENAI_MODEL=gpt-5.6-sol`. Модель должна быть доступна API-проекту владельца ключа.

Официальные материалы: [Models](https://developers.openai.com/api/docs/models), [Latest model guide](https://developers.openai.com/api/docs/guides/latest-model), [API quickstart](https://platform.openai.com/docs/quickstart/make-your-first-api-request).

## Рекомендуемый следующий этап

Для сотен тысяч документов стоит добавить embedding-индекс, гибридный поиск BM25/векторы,
reranking и метрики стоимости/качества ответов. Fine-tuning имеет смысл только после накопления
проверенного набора примеров «запрос → эталонный ответ»; для знаний из меняющихся документов
RAG остаётся основным механизмом.
