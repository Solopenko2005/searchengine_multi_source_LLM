Поисковая система на Java 17 и Spring Boot для индексации сайтов, PDF/DOCX-документов, лемматизированного поиска и ответов по найденным материалам с помощью OpenAI.

## Возможности

- многопоточная индексация сайтов и пакетная индексация PDF/DOCX;
- единый запуск, остановка и наглядный прогресс индексации;
- полнотекстовый поиск по леммам с ранжированием;
- просмотр найденного документа с цветовой подсветкой всех словоформ искомой леммы;
- RAG-ассистент по сайтам, документам и научным статьям с гибридным поиском по леммам и смыслу, потоковыми ответами, ссылками и экспортом в DOCX/TXT;
- фоновый семантический индекс на фрагментах документов, кэш тематик, остановка запроса и измерение времени этапов;
- LLM-анализ тематик по репрезентативным фрагментам всей доступной коллекции со структурированным JSON-ответом и локальным резервным алгоритмом;
- компактная кнопка профиля в верхней панели и выезжающий список источников с массовым выбором и удалением;
- рабочие группы: администратор делится своей коллекцией с посетителями по e-mail или ссылке-приглашению;
- каталог научных публикаций Crossref/Europe PMC и добавление выбранных статей в собственный индекс;
- пакетный импорт источников из CSV/XLSX;
- разграничение рабочих коллекций по владельцу и группе (`username`/e-mail в локальном режиме или `sub` JWT);
- Spring Security: локальная форма входа либо OAuth2 Resource Server с JWT;
- CORS allowlist, CSRF для сессий, роли USER/ADMIN и ограничение частоты LLM-запросов.

## Стек

Java 17, Spring Boot 2.7.18, Spring Security, Spring Data JPA, PostgreSQL, Liquibase, Jsoup, Lucene Morphology, Apache POI, PDFBox, OpenAI Responses API.

Полный проект хранится в одном репозитории:

- `Searchengine_1` содержит поисковое приложение и публичную страницу продукта;
- `authorization` содержит сервис регистрации, ролей и подтверждения администратора;
- `emailsender` содержит сервис отправки писем;
- `scripts` и `run-local.ps1` запускают все компоненты локально.

Для публичного Linux-сервера подготовлен Docker Compose-комплект с PostgreSQL,
Redis, всеми тремя Java-модулями, закрытой внутренней сетью и автоматическим HTTPS.
Инструкция находится в [deploy/README.md](deploy/README.md).

На публичном сервере администратор может открыть единую документацию всех API по
адресу `https://<домен>/api-docs`. В Swagger UI доступны спецификации поискового
приложения, сервиса авторизации и внутреннего сервиса отправки писем. Почтовые
операции документируются, но не публикуются напрямую в интернет.

## Быстрый запуск

1. Создайте PostgreSQL-базу, например `search_engine`.
2. Создайте локальный файл `.env` из примера и укажите в нём реальные параметры. Файл `.env` исключён из Git и автоматически читается приложением как при запуске из корня репозитория, так и из каталога `Searchengine_1`.

PowerShell:

```powershell
Copy-Item .env.example .env
notepad .env
```

В `DB_PASSWORD` должен находиться настоящий пароль пользователя PostgreSQL, заданный при установке или создании пользователя. Значение `change-me` из примера работать не будет. Переменные окружения операционной системы по-прежнему можно использовать — они имеют приоритет над `.env`.

Пример переменных для PowerShell без файла `.env`:

```powershell
$env:DB_URL="jdbc:postgresql://localhost:5432/search_engine"
$env:DB_USERNAME="postgres"
$env:DB_PASSWORD="change-me"
$env:APP_ADMIN_PASSWORD="change-me-too"
$env:OPENAI_API_KEY="your-api-key"
```

Пример для Bash:

```bash
export DB_URL='jdbc:postgresql://localhost:5432/search_engine'
export DB_USERNAME='postgres'
export DB_PASSWORD='change-me'
export APP_ADMIN_PASSWORD='change-me-too'
export OPENAI_API_KEY='your-api-key'
```

3. Запустите приложение:

```bash
cd Searchengine_1
mvn clean test
mvn spring-boot:run
```

Откройте [http://localhost:8080](http://localhost:8080) и войдите как `admin` (либо именем из `APP_ADMIN_USERNAME`). Если пароль не задан, одноразовый временный пароль выводится в лог при запуске.

### Запуск из IntelliJ IDEA

Запускайте класс `SearchEngineApplication` с рабочим каталогом `Searchengine_1`. Дописывать секреты в конфигурацию IDEA не требуется: приложение прочитает `.env` из корня репозитория. Альтернативный вариант — указать `DB_URL`, `DB_USERNAME` и `DB_PASSWORD` в поле **Environment variables** конфигурации запуска.

Ошибка `The server requested SCRAM-based authentication, but no password was provided` означает, что `DB_PASSWORD` отсутствует. Если пароль PostgreSQL забыт, задайте новый через pgAdmin либо выполните от имени администратора БД:

```sql
ALTER USER postgres WITH PASSWORD 'новый-надежный-пароль';
```

Затем запишите этот пароль только в локальный `.env`. Не добавляйте `.env` в Git.

## OpenAI

По умолчанию используется `gpt-5.6-terra` через Responses API; модель можно заменить переменной `OPENAI_MODEL`. Для более сложных задач можно выбрать `gpt-5.6-sol`, для более дешёвых массовых запросов — подходящую меньшую модель из доступных вашему API-проекту.

Подписка ChatGPT Plus/Pro и использование OpenAI API оплачиваются отдельно. Нужен API-ключ платформы OpenAI и активный API billing. Ключ передаётся только через `OPENAI_API_KEY` и никогда не должен попадать в Git.

Если ключ отсутствует или API временно недоступен, поиск продолжает работать, а ассистент формирует локальный ответ из найденных фрагментов.

### Бесплатный локальный режим LM Studio

API OpenAI не обязателен. Для работы без оплаты токенов установите LM Studio, загрузите совместимую модель и задайте:

```text
LLM_PROVIDER=LM Studio
OPENAI_ENABLED=true
OPENAI_BASE_URL=http://localhost:1234/v1
OPENAI_API_KEY=lm-studio
OPENAI_MODEL=local-qwen3-8b
```

`run-local.ps1` запускает локальный API LM Studio и загружает модель, если CLI установлен. Ответы и LLM-анализ тематик при этом не покидают компьютер.

Для смыслового поиска загрузите в LM Studio embedding-модель Nomic и оставьте включёнными параметры из `.env.example`. Построение векторов идёт в фоне: обычный поиск и ассистент доступны сразу, даже пока часть коллекции ещё обрабатывается. Состояние показывается на вкладке «Ассистент».

Подробнее: [ASSISTANT_README.md](Searchengine_1/ASSISTANT_README.md).

## Индексация и документы

- `POST /api/startIndexing` — начать полную индексацию сайтов (ADMIN);
- `POST /api/stopIndexing` — остановить активные задачи (ADMIN);
- `GET /api/indexing/status` — состояние, прогресс и статусы источников;
- `POST /api/addSite` — добавить и индексировать сайт (ADMIN);
- `POST /api/addPage` — добавить отдельную веб-страницу как самостоятельный источник (ADMIN);
- `POST /api/indexPage` — переиндексировать страницу (ADMIN);
- `POST /api/uploadDocument` — загрузить PDF/DOCX (ADMIN);
- `POST /api/importSources` — принять CSV/XLSX со столбцами `url`, `name`, `type` и поставить источники в очередь;
- `GET /api/scientific/articles` — найти публикации во внешних научных каталогах;
- `GET /api/scientific/recommendations` — предложить статьи по преобладающей тематике доступных документов;
- `POST /api/scientific/articles/add` — добавить выбранную публикацию в собственные источники;
- `GET /api/documents/indexing/status` — прогресс фоновой индексации документов текущего пользователя;
- `POST /api/documents/indexing/stop` — остановить только свою документную задачу;
- `GET /api/documents` — документы текущего пользователя;
- `GET /documents/{id}?query=...` — безопасный HTML-просмотр с подсветкой лемм.
- `DELETE /api/sources?ids=1&ids=2` — удалить выбранные источники и их поисковые данные (ADMIN; активную задачу сначала нужно остановить).

Статусы источника: `INDEXING`, `INDEXED`, `FAILED`, `STOPPED`. Индикатор в интерфейсе показывает готовность, процент выполнения и причину неполной индексации.

CSV/XLSX может содержать русские или английские заголовки (`url`/`ссылка`, `name`/`название`, `type`/`тип`). Значение типа `site`/`сайт` запускает обход домена, `page`/`страница` — индексацию одной ссылки. До 500 строк за одну загрузку.

## Интеграция с сервисом авторизации

Для production включите JWT-режим:

```text
SECURITY_MODE=jwt
AUTH_ISSUER_URI=https://auth.example.com/realms/search
AUTH_AUDIENCE=search-engine-api
CORS_ALLOWED_ORIGINS=https://search.example.com
```

Сервис авторизации должен выдавать JWT с корректными `iss` и `aud`, стабильным `sub` и массивом ролей в claim `roles`, например `["USER"]` или `["ADMIN"]`. Имена claims можно изменить через `AUTH_PRINCIPAL_CLAIM` и `AUTH_ROLES_CLAIM`. Если discovery недоступен, задайте `AUTH_JWK_SET_URI`. TLS должен завершаться на reverse proxy; наружу не следует публиковать PostgreSQL и внутренние административные порты.

### Роли и группы

- `ADMIN` видит все вкладки, индексирует, импортирует и удаляет источники, пользуется научной библиотекой и управляет группами;
- `USER` видит статистику, поиск, LLM-ассистента, профиль и источники администраторов тех групп, к которым подключён;
- при регистрации пользователь выбирает «Посетитель» или «Администратор»;
- посетитель сразу получает `USER`, а заявка администратора сначала получает `PENDING_ADMIN`. Полный доступ включается только после перехода по одноразовой ссылке из письма; ссылка действует 24 часа;
- адреса из `BOOTSTRAP_ADMIN_EMAILS` остаются аварийным способом создать первого администратора без письма. Несколько адресов разделяются запятыми;
- администратор создаёт группу на вкладке «Управление», добавляет зарегистрированный e-mail либо копирует ссылку-приглашение.

Данные изолированы по владельцу: один администратор не видит источники и задания другого администратора. Посетитель получает доступ только к источникам администраторов тех групп, в которые он вступил.

### Научная библиотека

В выпадающем списке автоматического поиска доступны Crossref, Europe PMC, Semantic Scholar, arXiv и DOAJ. Ресурсы без открытого программного поиска сохранены отдельными ссылками. Блок рекомендаций определяет преобладающую тему только среди доступных документов пользователя и предлагает публикации из открытых каталогов.

### Восстановление пароля

Ссылка «Забыли пароль?» отправляет одноразовую ссылку на 10 минут. Токен хранится в БД, используется один раз, а форма не раскрывает, зарегистрирован ли введённый e-mail. Тот же почтовый сервис отправляет подтверждение роли администратора.

Для Gmail включите двухэтапную аутентификацию, создайте отдельный 16-символьный пароль приложения и укажите локально:

```text
MAIL_USERNAME=ваш_адрес@gmail.com
MAIL_PASSWORD=16-символьный_пароль_приложения
```

Обычный пароль Google в SMTP не принимается. `run-local.ps1` запускает сервис на порту `8771`, проверяет `GET /api/v1/email/health` и выводит безопасное предупреждение, если SMTP не прошёл проверку. Секреты из `.env` нельзя добавлять в Git.

## Локальный запуск всех сервисов

Сервисы авторизации и отправки писем уже входят в этот репозиторий. Заполните `.env`, затем выполните из корня проекта:

```powershell
powershell -ExecutionPolicy Bypass -File .\run-local.ps1
```

Скрипт запускает сервис авторизации на порту `5555`, при наличии SMTP-настроек — сервис писем на `8771`, ждёт готовности и запускает поисковую систему на `8080`. Регистрация доступна по адресу `http://localhost:8080/register`. Роль выбирается на форме регистрации; новый администратор должен подтвердить рабочий e-mail, кроме адресов из `BOOTSTRAP_ADMIN_EMAILS`.

## Готовность и ограничения

- обычный поиск работает сразу, а фоновый смысловой индекс можно остановить и продолжить без потери прогресса;
- пустые и технические страницы получают завершённый статус `SKIPPED`, поэтому очередь не зацикливается и индикатор достигает 100%;
- гибридный RAG использует леммы и HNSW-векторы, выбирает до 15 различных источников и требует ссылку для каждого содержательного утверждения;
- тематический анализ отдаёт приоритет целям, методам, результатам и выводам исследования, а библиографические, регистрационные и издательские блоки понижает в рейтинге;
- текущая одноузловая конфигурация подходит для локальной работы и пилотного размещения с десятками тысяч страниц. Для нескольких серверов или миллионов фрагментов нужны внешняя очередь заданий и векторное хранилище уровня pgvector, Qdrant либо OpenSearch;
- Spring Boot 2.7.18 оставлен ради совместимости с кодом `javax.*`; плановая миграция на Spring Boot 3 потребует перехода на `jakarta.*` и обновления Spring Security DSL.

Проверка готовности к размещению и следующий план приведены в [docs/HOSTING_READINESS.md](docs/HOSTING_READINESS.md).
